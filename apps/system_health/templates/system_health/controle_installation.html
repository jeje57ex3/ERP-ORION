Pourquoi pas la suite de tests

Le dépôt porte 3 230 tests automatisés. Ils ne conviennent pas à un contrôle mensuel du serveur, pour trois raisons :

  • pytest ne figure pas dans requirements.txt, donc n'est pas installé ici. L'y ajouter mettrait l'outillage de test en production.
  • La suite construit une base de données entière en rejouant toutes les migrations, puis la détruit. Sur le serveur qui porte vos données, ce n'est pas une opération qu'on planifie.
  • Surtout : elle vérifie le code, qui est exactement celui qu'un commit a déjà validé. Le rejouer chaque mois ne révèle rien de nouveau.

Ce qui dérive, c'est l'installation : une migration oubliée, un service arrêté, un planificateur vide, une sauvegarde qui date, un disque qui se remplit. C'est ce que vérifient les contrôles ci-dessus. Trois d'entre eux sont repris de la suite parce qu'ils portent bien sur l'installation : les vérifications système de Django, l'absence de migration en attente et le chargement de l'arbre des adresses.
