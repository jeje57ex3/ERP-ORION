À quoi ça sert

L'écran des disques voit ce que le système d'exploitation voit, et rien de ce que l'hyperviseur sait. Deux questions restaient sans réponse :

  • « ai-je bien branché un disque sur la VM ? » Un disque correctement ajouté mais que le noyau n'a pas vu ressemble exactement à un disque jamais ajouté.
  • « quelle taille puis-je allouer ? » La place libre est sur les pools de stockage de l'hôte, invisibles d'ici.

Lecture seule, par construction. Ce client n'émet que des requêtes GET : il n'y a aucune méthode d'écriture à désactiver, il n'en existe pas. Le jeton enregistré ici ne peut donc rien modifier sur l'hyperviseur depuis l'ERP, même s'il en a le droit côté Proxmox.

Créer le jeton dans Proxmox

  1. Datacenter → Permissions → API Tokens → Add
  2. Choisissez un utilisateur, un nom de jeton, et décochez « Privilege Separation » seulement si vous savez pourquoi.
  3. Copiez le secret : Proxmox ne le réaffiche jamais.
  4. Datacenter → Permissions → Add → API Token Permission : donnez-lui le rôle PVEAuditor sur /.
Donnez-lui un rôle de lecture seule (PVEAuditor, ou VM.Audit + Datastore.Audit). Rien ici ne peut l'imposer : c'est une consigne. Un jeton d'hyperviseur logé dans la machine virtuelle qu'il gouverne renverse la confiance — autant qu'il ne puisse que regarder.

Disques & stockage

Ce que l'ERP ne fait pas

Il n'ajoute pas de disque. Créer et rattacher un disque est une écriture sur l'hyperviseur, et ce client ne sait que lire. Cette page vous dit si un disque est branché, s'il est visible du système, et quelle place reste disponible — l'ajout se fait dans Proxmox, puis l'écran des disques prend le relais pour le partitionner, le formater et le monter.
